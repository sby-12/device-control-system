# 设备接口隔离改造 · 代码逻辑审查报告

审查时间：2026-10-31
改造主题：连接窗口设备机型下拉框 + 新增三个品牌设备适配库 + 主窗口设备槽位接口化
编译结果：整个解决方案 Build 零错误（仅历史遗留警告）

## 一、本轮改动清单（逐文件）

### 1. 接口库 InstrumentInterfaceLibrary（新增）

定义三个接口，net48 目标框架，与旧库一致：

- IScope：示波器 27 个成员（Open/Close、时基、档位、触发、保存、深存储、实时读使能等）
- IPowerSource：电源成员（设电压/电流、过流过压保护、输出开关、状态回读）
- ISignalSource：信号源成员（ValueSet、Apply、单双脉冲输出、任意波下载）

设计要点：接口成员签名尽量沿用旧类现有方法名（如 SetOverLoadVolatage 保留原拼写），旧类实现接口时方法体一行不改，降低回归风险。

### 2. 四个旧类实现接口（方法体零改动）

- OscilloscopeClass:IScope —— 只做了三件事：DeepSavePointsApplied 由 public 字段改为自动属性（接口要求）；新增 DeviceName、SupportDeepSave=true、DataReadEnabled/ChannelMask/ReadChannelIndex 三个映射到 translateClass 的成员（原来界面代码直接访问 translateClass.EquipDataRead 等内部字段）；DeepSaveActive 包装原有 DeepSaveMode 字段。
- N36200Class:IPowerSource —— 纯加 :IPowerSource 和 DeviceName。
- N2410Class:IPowerSource —— 补 6 个接口要求的成员：SetOutput 包装原有 SetChannelOpen；GetDeviceStatus/GetBackPower/GetBackTemperature/FactoryReset/SetOverLoadVolatage 直接抛 NotSupportedException（这些功能 N2410 手册里没有）；DeviceName。
- SignalClass:ISignalSource —— 纯加 :ISignalSource 和 DeviceName。

风险评估：旧类的方法体一个没动，旧设备（RIGOL+NGI+原信号源）的原有行为理论上与改造前完全一致，唯一需要回归的是 N2410 的 SetOverLoadVolatage 从"不存在"变成"抛异常"——界面上 N2410 区块没有过压保护按钮，触发不到。

### 3. 三个新适配库（全部编译零错误）

每个库由"设备类 + ScpiTcp（TCP 通讯）"两个文件组成。ScpiTcp 是同步 TcpClient 加 lock，Query 逐字节读到换行；SendAsync/QueryAsync 用 Task.Run 包装同步方法。

- LeCroyScopeLibrary：SCPI 指令按力科 MAUI 手册直译。Open 时不发特殊指令；Start/Stop 用 TRMD AUTO/STOP；Single 用 ARM；Auto 用 AUTO_SET；通道映射 MapCh 把通用的 CHANnel1 转成力科的 C1 格式。
- It16000dLibrary：OpenTranslate 里先发 SYST:REM 切远程模式（关键，不发这条很多 SCPI 指令会被前面板锁定）。SetOverLoadCurrent 用 CURR:PROT，SetOverLoadVolatage 用 VOLT:PROT，与学长之前"过流保护指令错写成限电压"的 bug 区分开——这里两条指令用的是手册里各自独立的寄存器。
- Sdg6000xLibrary：单位约定写在注释里——脉宽/间隔按纳秒传入，内部乘 1e-9。用 InvariantCulture 格式化数字，避免中文系统把小数点写成逗号导致指令解析错误。

### 4. 主工程改动

- DeviceFactory.cs（新增）：设备型号常量 + CreatePower/CreateScope/CreateSignal 三个静态工厂方法。Modbus 站号约定 A=1、B=2 在这里写死。
- IpStorage.cs：存档格式从两段（IP,端口）升级为三段（型号,IP,端口）；TryGet 兼容旧格式，读旧文件不报错；新增"电流源A/电流源B"键，保留旧键做迁移回退。
- ConnectInit.xaml + .cs（重写）：四行设备选择区（电流源A、电流源B、示波器、信号源），每行 = 机型下拉框 + IP + 端口 + 连接按钮。连接流程：校验 IP/端口 → DeviceFactory 创建 → OpenTranslate → OwnerMain.Attach* → 存档。
- MainWindow.xaml.cs：
  - 设备字段从具体类改为接口类型（IPowerSource powerSourceA/powerSourceB、IScope、ISignalSource），外加四个机型字符串字段。
  - 构造函数不再 new 任何设备，设备对象只由连接窗口 Attach 进来。
  - 新增 AttachPowerA/AttachPowerB：内部按 is N2410Class / is N36200Class 接各自的回读回调（N3416InfDisplay/N3621InfDisplay/WriteDataLog），N36200 附带 SetChannelMode+SetChannelCvOrCc。只有具体旧类才有这些回调，新设备 Attach 后没有状态回读属预期行为。
  - 新增 AttachScope：is OscilloscopeClass 才接 reciveState/thisNetPublicTool/FindChannel 回调。
  - 新增 AttachSignal：is SignalClass 才接回调 + Init。
  - UpdatePowerBlockAHeader/B 状态文字改为"电流源A（机型）已连接"式，机型动态显示。
  - 属性重构：Power36200 删除；AiPower = powerSourceA ?? powerSourceB（AI 助手优先用 A 槽）。
  - 全部 oscilloscopeClass.translateClass.EquipDataRead/CHANNum/Chnumber 替换为接口的 DataReadEnabled/ChannelMask/ReadChannelIndex（共 30 余处，replace_all 完成）。
  - N2410 区块的通道选择按钮（BtnCh1/BtnCh2）改为仅当 is N2410Class 时执行，否则弹 Toast 提示"通道选择是 N2410 专属功能"。
  - Image_MouseDown 退出时的 :OUTP1 OFF 加了 is SignalClass 守卫，新信号源不会因退出误发指令。
  - BtnTestff/BtnTestFanff 的波形数据原来调 SignalClass.WaveSine/WaveSquare，改为 MainWindow 本地静态方法（公式与原版一致），并加 null 检查，新信号源没有这两个静态方法的问题被绕开。
- MainWindow.xaml：6 处显示文字从"电源N3416/N3620/N2410"改为"电流源A/电流源B"，控件名一律未动。
- AiTools.cs / AiAssistantWindow.xaml.cs：字段和属性全部改 IScope/IPowerSource，调用点同步改为 Oscilloscope / AiPower。
- csproj/sln：登记 DeviceFactory.cs、三个新库引用、三个新库工程条目，sln 保持 GBK 编码。

## 二、逻辑走查（改造后的完整链路）

1. 启动 → MainWindow 构造 → new ConnectInit（此时没有任何设备对象）。
2. 连接窗口载入 → IpStorage 读存档 → 机型下拉框选中上次用的型号，IP/端口回填。
3. 点"通信连接" → 校验 → DeviceFactory 按机型 new 对应类 → OpenTranslate 建链 → 发握手（旧 Modbus 类发自身初始化，SCPI 类 IT16000D 发 SYST:REM，LeCroy 发 *IDN? 核对型号）→ Attach* 注入主窗口 → 存档。
4. 主界面按钮 → 一律走接口调用 powerSourceA/powerSourceB/Oscilloscope/SignalClass 接口成员。
5. 状态回读 → 只有旧类有回调，新设备无回读（预期，见未实现清单）。
6. 关闭软件 → Image_MouseDown 守卫后只对 SignalClass 发 :OUTP1 OFF。

## 三、风险评估（按严重程度排序）

### 高风险（必须真机验证后才能放心）

1. SDG6000X 双脉冲脉宽系数：双脉冲界面传给 OutputOneDifferentPulses 的纳秒值带 t*8.12 系数，这个映射是我定的，未经任何标定。首个测试必须用示波器实测脉宽并反推修正系数。
2. LeCroy 保存图片语法：HCSU 的 DIRECTORY/FILENAME 参数格式是从手册直译的，路径写法（带不带引号、用正斜杠还是反斜杠）各机型有差异，第一次保存图片时盯着示波器屏幕看是否成功。
3. IT16000D 的保护寄存器：CURR:PROT 和 VOLT:PROT 是手册原文，但学长之前 N36200 的教训说明"手册写了不等于设对了"。联调时设一个较小的过流值，用电子负载或直接短路验证确实在过流点保护。

### 中风险（逻辑正确但值得留意）

4. Modbus 站号绑定假设：A=1、B=2 写死在 DeviceFactory。如果两台 NGI 电源站号相同（出厂默认常常都是 1），会冲突。联调时若发现"设 A 的时候 B 跟着变"，就是站号撞了，需要在连接窗口加站号输入框。
5. 重复连接不释放旧设备：多次点连接会覆盖引用，旧 TCP/串口连接悬空。软件运行期间一般只连一次，风险可控；频繁换设备时重启软件即可，长期可以加 Attach 前 Close 旧设备的逻辑。
6. WriteDataLog 日志归属：NGI 库按 Modbus 站号回传 1/2，恰好对应 A/B 槽；但如果用户把 N36200 连到 A 槽、N2410 连到 B 槽，站号仍然是 A=1/B=2，日志归属正确。此假设成立的前提是工厂约定不变。

### 低风险（已规避但记录在案）

7. LeCroy 的 DataReadEnabled 等占位属性：AttachScope 后如果界面代码（非旧类路径）读这些属性，得到的只是默认值 false/0，不会有曲线数据也不会有报错，表现为"读波形没反应"。已在未实现清单列第一项。
8. AiPower 回退逻辑：AI 助手优先取 A 槽，A 没连取 B 槽。如果两个槽都连了不同机型，AI 只能控制 A 槽，向 AI 询问 B 槽操作会失败。后续可给 AI 工具加槽位参数。
9. IpStorage 旧格式兼容：TryGet 读旧两段格式时型号返回空串，连接窗口会显示默认下拉项，用户重新选一次机型并连接后自动升级为三段格式。

## 四、遗留历史问题（非本轮引入，供后续清理）

- MainWindow.xaml.cs 第 22/23 行 using System.IO / System.Reflection 重复声明（编译警告 CS0105）。
- MainWindow.xaml.cs 第 1085 行一处异步调用未 await（警告 CS4014），在频繁点击时可能有小概率竞态。
- MainViewModel.cs 的 _seriesCount2~5、JiXianName、WriteDataUpLimit 多个字段赋值后从未使用（警告 CS0414/CS0219）。
- ValueSourceN2410ClassLibrary 的 TcpTranslateClass.cs 第 171 行 catch 了 ex 但没用（原样保留）。

## 五、结论

改造目标全部达成：连接窗口可选 4 类设备槽位 × 3 种机型，设备创建走工厂方法，主界面全部通过接口调用，选择结果持久化存档，旧设备行为零改动，整解决方案编译零错误。剩余工作全部集中在真机联调与未实现清单的功能补齐上，代码层面没有阻塞项。
